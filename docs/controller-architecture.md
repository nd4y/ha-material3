# Архитектура reconcile-контроллера

Срез: office_climate 0.4.42, политика 0.4.2, 30.10.2026. [Основные блок-схемы](automation-flow.md). Python backend и HACS frontend имеют отдельные версии и поставку. Пути ниже обозначают модули backend; они не являются утверждением, что Python-интеграция входит в архив HACS этого репозитория.

## Поток данных и ответственность

| Этап | Модуль backend | Что обеспечивает |
| --- | --- | --- |
| Входящие факты | `reporting.py`, `ha_projection.py`, `freshness.py` | Происхождение, эпоха, диапазоны, возраст, неизвестные поля |
| Пользовательское намерение | `intents.py`, `user_intents.py`, `gateway.py` | Группы шкал, ручные владельцы, Off, ревизия и сохранение |
| Снимок входов | `custom_components/office_climate/policy_inputs.py` | Один набор показаний, целей, таймеров и памяти |
| Потребность комнаты | `policy.py`, `co2_control.py`, зафиксированные Jinja assets | Тепловой запрос, CO₂, PM2.5, ограничения шума, PI |
| Совместное решение | `manual_plan.py`, `office_plan.py`, `planner.py`, `authority.py` | Ручные ограничения, эффекты пресетов, тепловая совместимость |
| Команды | `commands.py` | Возможности устройства, диапазоны, ожидаемые эффекты и предварительные условия |
| Применение | `runner.py`, `executor.py`, `goals.py` | Повторная проверка перед отправкой, актуальная цель, операция в полёте, неопределённый результат |
| Остановка | `stop_watch.py` и транспортные наблюдатели | Сохранённый бюджет Off, поздний On, отсутствие абсолютной гарантии порядка пакетов |
| Подключение HA | `runtime.py`, `active.py`, приёмники интеграций | Подписки, доступность, обновление проекции, запуск тиков |

## Инварианты

- Расчёт не отправляет команды и не меняет приборы частично.
- Команда не применяется без последней проверки по текущему снимку и намерению.
- Ручной параметр учитывается как ограничение при подборе других параметров.
- Неизвестное, устаревшее и неподтверждённое не становятся нулём или разрешением.
- CO₂-приток независим от теплового режима AC; минимальная уставка притока не означает Off вентилятора.
- Комнатный нагрев и охлаждение не запускаются навстречу друг другу.
- Только AC имеет фиксированную паузу компрессора. Для электрического обогревателя работает температурный гистерезис без 120-секундного запрета запуска.
- Дедупликация не превращает новый цикл On → Off → On в уже выполненную старую команду.
- Принятие сервиса, намерение, отправка и входящее подтверждение - отдельные стадии.
- Неопределённое исполнение сохраняется до разрешения; обычный тик не создаёт бесконечных повторов.

## Границы покрытия и выпуска

В 0.4.42 при проверке на устройстве добавлена обработка входящего SPEED=8 в Turbo бризера. Это не ручная ступень скорости и не самостоятельное подтверждение режима: предыдущая числовая скорость снимается, питание и preset берутся только из MODE. Неизвестные значения по-прежнему отклоняются.

В 0.4.41 ревью схем выявило и устранило четыре противоречия: лишний Off при переходе AC через вентиляцию; продление компрессорного таймера переходами Off/вентиляция; преждевременное завершение цикла общим планировщиком; задержку новой цели обогревателя до фонового интервала. Добавлены проверки границ таймера, направлений режима, ручных ограничений и сохранения ожидающей уставки перед отправкой. Документация также исправляет описание фактической очереди событий и убирает несуществующую зависимость старта AC от предела подогрева притока.

Проверки группируются по значимым классам и границам: диапазоны, владельцы, Auto/Manual/Off, ошибки и неизвестные поля, актуальность ревизий, поздние подтверждения, рестарт и остановка. Полный набор модульных тестов и изолированные HA harness проверяют адаптер и исполнение. Большая температурная сетка запускается при изменении классификации/округления; удаление таймера обогревателя эти функции не меняет.

Синтетические проверки не доказывают радиодоступность, исправность сети или фактический нагрев. При выпуске отдельно проверяются точные установленные файлы и входящие подтверждения в HA. Физическая эффективность и долговременная надёжность требуют собственных наблюдений и не следуют из одного успешного переключения.

## Что изменилось относительно старых схем

| Ранее в документации | Текущий контракт |
| --- | --- |
| Набор pure Jinja-формул описывает всю автоматику | Формулы - только часть сохраняющего состояние reconcile-контроллера |
| Свежесть как относительное пожелание | Пользовательская цель CO₂ в ppm; запрос скорости рассчитывается по отклонению |
| Нагрев притока мешает запуску охлаждения | Приток продолжается; только автоматический подогрев снижается до 5 °C |
| Любой отсутствующий отчёт ошибки AC запрещает Auto | Узкое исключение для необязательного поля при полном достоверном снимке и чистой блокировке |
| Обогревателю нужна пауза 120 с | Удалена в 0.4.40; гистерезис и реальные проверки сохранены |
| Успешная отправка равна результату | Требуется квалифицированное входящее подтверждение; неопределённость сохраняется |

Публичные `controller/*.jinja` и [каталог их условий](condition-index.md) остаются полезным описанием переносимых формул. Они не содержат Python-планировщик, реестр входящих отчётов и цикл исполнения. Конфигурация конкретного дома, адреса, идентификаторы устройств и журналы в документацию не включаются.
